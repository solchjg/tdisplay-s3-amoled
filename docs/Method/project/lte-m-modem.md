# LTE-M modem evaluation

A plain LTE-M modem gives the device an ordinary IP link over cellular, so the
WiFi senders (ntfy, mail, ThingsBoard over HTTP) can run over it with no vendor
cloud between the device and its peers. No FSD section covers it yet: this page
describes the evaluation that comes before `/define`, not product behaviour.

The evaluation board is the user's **LilyGO T-SIM7080G-S3 V1.0** (ESP32-S3,
SIMCom SIM7080G LTE-M / NB-IoT with GNSS, AXP2101 PMU), run on its own, not
wired to the T-Display. Its modem is the one a modem-only add-on board would
carry, so coverage, attach time, power and GPS results carry over.

## Board

From LilyGO's `utilities.h` and `ATDebug.ino` (repo `Xinyuan-LilyGO/LilyGo-T-SIM7080G`):

| Item | Value |
|------|-------|
| Modem UART | UART 1, ESP32-S3 RX GPIO 4, TX GPIO 5, 115200 baud, no flow control |
| Modem control | PWRKEY GPIO 41 (low, high 1 s, low toggles power or wakes from PSM), DTR GPIO 42 (held low), RI GPIO 3 |
| PMU | AXP2101 at 0x34, SDA GPIO 15, SCL GPIO 7, IRQ GPIO 6 |
| Modem rail | DC3 at 3.0 V |
| Level shifter rail | BLDO1 at 3.3 V, never off |
| GPS antenna rail | BLDO2 at 3.3 V, on only while seeking a fix |
| Battery-side connector P4 | 4 pins: 1 RXD GPIO 44, 2 TXD GPIO 43, 3 3.3 V (DCDC1), 4 GND; the product build's sensor bus (SDA 43, SCL 44). **Caution:** this is the Qwiic order (GND, 3.3 V, SDA, SCL) reversed, so a Qwiic cable plugged straight in puts 3.3 V on SCL and GND on SDA, and its plug may not fit P4; make up or meter the lead before first power-up (black GND, red 3.3 V, blue GPIO 43, yellow GPIO 44) |
| Limits | A SIM fitted after power-up is not seen; GNSS and LTE share the RF path, so one runs at a time |
| Status screen (optional) | SSD1306 or SH1106 (most 1.3" modules; `PROBE_OLED_SH1106`, workflow test `sh1106`) 128x64 on I2C port 1: GND, VCC to 3V3, SDA GPIO 13, SCL GPIO 21 (camera header pins, free without a camera), address 0x3C or 0x3D |

## Probe

[`commissioning/modem-probe`](../../../commissioning/modem-probe/main/main.c) is the
evaluation program (never released). Each run:

1. **Rails and battery.** Sets the AXP2101 rails and prints the battery state
   (`battery present= vbus= current= charger= charge_on=`, with the raw AXP2101 status
   registers).
2. **Wake.** Sends a plain `AT` every 100 ms: for 200 ms before the PWRKEY pulse when the
   modem is expected in PSM, 1.5 s otherwise, then up to 30 s after it. The `modem answers`
   line splits the wake into `ask_ms`, `pulse_ms` and `after_ms`, and `tries=` counts the
   ATs before and after the pulse.
3. **Modem facts.** Prints the firmware, SIM state, ICCID and signal.
4. **GPS (optional, first run only).** Seeks one fix with LTE off, since GNSS and LTE share
   the RF path. When the modem stops answering during the search, it is woken and GNSS
   switched on again, up to three times, before the search is abandoned.
5. **Attach.** Registers on LTE-M and times it. With PSM, a later run whose modem is still
   registered uses that registration (`psm_resume`, with the `AT+CEREG?` tries it took
   over up to 5 s) instead of a full attach.
6. **Clock.** Sets the clock from the modem's network time (`AT+CCLK?`, kept through PSM;
   `network time utc=…`), or by SNTP over PPP when the modem has none.
7. **Send.** Brings up PPP through `esp_modem` and POSTs one telemetry record straight to
   ThingsBoard: the §32.3 shape with fixed test values plus `probe_*` keys (run, attach
   time, CSQ, battery mV, the previous run's bytes as `probe_prev_tx`/`probe_prev_rx`;
   after a GPS search also `probe_gps_s`, -1 for no fix, and `latitude`/`longitude`).
   `probe_run` counts every wake, sent or not, so a gap in it is a lost record. On the
   first run it also sends one alert through the shared `ntfy_tx`, unchanged from the
   WiFi path.
8. **Report.** Leaves PPP and prints the run's timings and running totals, with the bytes
   moved over PPP in each phase (`bytes ppp_setup|sntp|thingsboard|ntfy|ppp_close tx= rx=`,
   `sntp` only when it ran; lwIP's MIB2 octet counters: sent bytes as framed on the UART,
   received bytes after unframing) and for the whole run. The battery state, the
   `modem answers` line and the PSM-resume line are printed again after the run line,
   since after a timer wake USB connects too late to show the first ones.
9. **Sleep.** Before deep sleep a full attach prints the network's grant decoded
   (`psm grant active_s= tau_s=`; a PSM resume reports no timers).

With a screen fitted, five lines (Terminus 6x12, `commissioning/common/oled/font6x12.c`,
generated by `shared/tools/bdf_to_c.py` from `ter-u12b.bdf`) show the run with the GPS
result (seconds to the fix, `none`, or `-` when not tried; kept for later runs), the
network and band, attach time and CSQ (the search's progress while seeking), the
ThingsBoard and ntfy results, and the time awake and battery voltage. The panel is
blanked before deep sleep.

### Options

Options are under "Modem probe" in `idf.py menuconfig`:

- **APN**, default `iot.1nce.net`.
- **Radio access**: LTE-M, NB-IoT or both.
- **Network lock** (`PROBE_PLMN`, MCC+MNC such as 310260 T-Mobile, 310410 AT&T, 311480
  Verizon). A full attach sends `AT+COPS=1,2`, with no fallback, so a refused roam shows as
  no registration; with `PROBE_PLMN_FALLBACK` it sends `AT+COPS=4,2`, that network first and
  then automatic choice. Empty undoes an earlier lock.
- **Senders**: ThingsBoard URL and token, ntfy URL, topic and token.
- **GPS**, with its search limit.
- **PSM**: TAU 1 h, active time 10 s.
- **Minutes between runs.** With 0 it runs once and then prints the signal every 30 s;
  above 0 it deep-sleeps between runs, the modem in PSM or, without PSM, powered down so
  each run is a cold attach.

### Settings image

The repository is public, so no build carries a secret. The ThingsBoard token and the
ntfy topic and token come from a settings image: NVS namespace `probe`, keys `tb_token`,
`ntfy_topic` and `ntfy_token` (optional), read at boot and logged as `settings image
tb_token=set|none …`; without one the menuconfig values are used, for a local build. Make
it from a copy of [`settings.csv.example`](../../../commissioning/modem-probe/settings.csv.example)
named `settings.csv` (ignored by git) with
`python -m esp_idf_nvs_partition_gen generate settings.csv settings.bin 0x6000`
(pip package `esp-idf-nvs-partition-gen`), keep it off the repository, and flash
`settings.bin` at `0x9000` (the `nvs` partition) with the build.

### Builds without a toolchain

Run the "Commissioning aids" workflow by hand: `modem_apn`, `modem_tb_url`, `modem_ntfy`
(the base URL only), `modem_tests` (`gps`, `psm`, `sh1106`, `fallback`), `modem_every` and
`modem_plmn` set the same options. A hand-started run also replaces the one commit on the
`firmware-drops` branch with its images (one folder per program, plus `BUILD.txt` naming
the run, commit and inputs), so a session that reaches git but not artifact storage can
fetch and flash them. The build fails if the `MODEM_PROBE_TB_TOKEN` secret turns up in the
image.

### Log

Lines start with `modemprobe:`; `CHECK` marks a result to look at. The run summary is
`modemprobe: run=<n> awake_ms=… attach_ok=… attach_mean_ms=… thingsboard_ok=… ntfy_ok=… vbat_mv=…`.

## Bench steps

1. **Smoke test.** Fit an IoT SIM (before power-up) and the LTE antenna. Flash the
   probe with no ThingsBoard or ntfy set: `AT+CPIN?` answers `READY`, `AT+CSQ` is not
   `99`, and `registered attach_ms=` appears.
2. **Senders.** Set the ThingsBoard URL and the ntfy server, and flash the settings image: `thingsboard
   status=200` and `ntfy ESP_OK` appear, and the record and the alert arrive.
3. **GPS.** Fit the GPS antenna and enable GPS: `gps fix lat= lon= after_s=` appears,
   outdoors or at a window.
4. **Power.** Enable PSM, set 60 minutes, power the board from a LiPo through a
   current meter: the current between runs, and the charge of one run from its
   `awake_ms` and the meter. These are whole-board figures, including the ESP32-S3. A
   meter on USB instead reads VBUS, so take the battery out or let it charge full
   (`charger=off`) first, and check that it resolves µA, not only mA steps.
5. **Soak.** 24 h at 60 minutes: the ThingsBoard records against their `probe_run`
   (counted on every wake, so a gap is a lost record), or `thingsboard_ok` against `run`
   in the log.

Proposed pass marks: attach within 60 s, at least 95% of records arrive, under 1 mAh
a run, a GPS fix within 2 min. On the bench this board sits in SLOT3; SLOT1 holds the
T-Display.

## Results

Measured on the bench with a Hologram SIM (APN `hologram`), runs every 10 minutes with PSM
unless a row says otherwise:

| Item | Value |
|------|-------|
| Network | Verizon (311480), roaming (`+CEREG` stat 5), LTE-M band 13, CSQ 21–24 |
| Full attach | 38 s (after a GPS search); a PSM resume is registered at once (`attach_ms=5`) |
| PSM grant | asked 10 s active time and 1 h TAU; granted 300 s active time and 18600 s TAU, so the modem stays awake 5 minutes after each run |
| Wake from PSM | 3.0 s in all: 0.3 s asking, the 1.1 s pulse, and 1.6 s until the modem answers |
| Time awake | 8.7 s for a PSM-resumed run (registered on the second `AT+CEREG?`, 0.5 s after waking); about 130 s for a first run with a GPS search |
| Network time | Verizon supplies it (`AT+CCLK?`), so no SNTP runs |
| Data | one ThingsBoard POST moves 1.4–1.8 kB up and 5.8–10.4 kB down, mostly the TLS handshake; a PSM-resumed run moves 7–12 kB in all, a first run with the ntfy alert 18–21 kB |
| GPS | cold fix in 59–69 s at a window |
| Battery | an 18650 alone carries the board; full at 4.2 V the charger reports `charger=off` with charging enabled (`charge_on=1`), which is the normal end of charge |
| Soak | 24 h at 60-minute runs with PSM, the board on its own supply: 25 of 25 records arrived (runs 1–25, Nov 4 7:52 PM to Nov 5 7:58 PM EST), no gaps; each run starts about 15 s later than the one before |

## Carriers

The modem only asks for its PSM timers; each network grants its own, and the grant can
change between cells. Network time and attach time differ by network too. A roaming SIM
such as Hologram's can attach to several US networks, so the probe logs the grant on
each full attach, and `PROBE_PLMN` locks a test build to one network (310260 T-Mobile,
310410 AT&T, 311480 Verizon). Which networks the SIM may use for LTE-M is set by the SIM
provider, not by the modem.

Measured with the Hologram SIM at the bench, one network locked per build, PSM on, runs every 10 minutes:

| Network | Band | Full attach | PSM grant (active, TAU) | Network time at attach | PSM-resumed run awake |
|---------|------|-------------|-------------------------|------------------------|-----------------------|
| Verizon (311480) | 13 | 10.5–38 s | 300 s, 18600 s | yes | 8.7 s |
| T-Mobile (310260) | 12 | 34.6 s | 10 s, 3600 s | no (SNTP) | 7.3 s |
| AT&T (310410) | 12 | 16.9 s | 16 s, 3600 s | no (SNTP); set by the next run | 9.5 s |

T-Mobile and AT&T grant about what the modem asks; Verizon keeps the modem awake 5 minutes after each run.

A lock is refused (`+CME ERROR: SIM failure`) until the SIM is up after `AT+CFUN=1`, so the probe retries it. The modem keeps a lock through power-off; a build with no network set undoes it (`network lock undone`), and on automatic choice this SIM picks AT&T at the bench.

## Antenna

The SIM7080G has one LTE port (u.FL) with no DC on it; only the GPS port is powered, from
BLDO2. An amplified LTE antenna is a cellular signal booster, which must be an FCC-certified
unit, so more range comes from a passive antenna and the cable: a single-port antenna
rated for 698–960 MHz (bands 12 and 13 carry LTE-M on AT&T and Verizon), an omni on a
pole where several towers or networks may serve, or a directional yagi or panel aimed at
one tower for a far site. Datasheet gain is often quoted at 2.6 GHz and runs 3–5 dB lower
at 700 MHz. The u.FL-to-SMA pigtail stays short, with long runs on LMR-400 to an N
connector. LTE-M's coverage enhancement adds up to about 15 dB on top.

## Inputs to `/define`

Requirements the user has asked for, drafted in FSD §35 (T-SIM7080G Build) with the parity requirements around them:

- `[user]` The device adapts to the network's PSM grant: on each full attach it reads the
  granted active time and TAU, and when PSM is not granted or the active time is too long
  (proposed: over 60 s) it powers the modem off between readings and attaches cold.
- `[user]` A T-SIM7080G build drives an e-paper display above 40 °F and an OLED below it.
- `[user]` An off-board button.
- `[user]` Settings from a microSD card.
